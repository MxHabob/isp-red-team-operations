# Documentation

## Responsibility
Architecture documentation, threat models, attack models, operational guides, data classification, evidence lifecycle, lab guides, ADRs, glossary, and data model.

## Rules
- Documentation must reflect actual implementation — not aspirational design.
- Architecture decisions go in `decisions/` as individual ADR files.
- Security-sensitive operational details should reference controlled storage, not be placed inline.
- Keep documents focused — one topic per document.
